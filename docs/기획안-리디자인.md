# 나주한조각 — 리디자인 기획안

> 운영 제약 고정: **비로그인(localStorage만)·백엔드/DB 0·단일 API(`/api/merchants`)·전부 실데이터·정적 큐레이션(코드/JSON)**. 아래 모든 제안은 이 네 가지를 깨지 않는다.

---

## 1. 문제 정의 (지금 왜 복잡한가)

운영자(사장)의 1순위 피드백은 **"탭이 너무 많다. 원래는 딱 하나의 기능으로 통합하려던 의도였다"**이다. 코드를 보면 이 직감이 정확하다.

**현재 4탭은 "기능 분리"가 아니라 "필터 분리"다.** 같은 데이터(`/api/merchants` 하나)를 다른 필터로 보여주는 4개의 뷰일 뿐이다.

| 탭 | 실제 하는 일 | 중복 |
|---|---|---|
| **가이드** (`page.tsx`) | merchants(food,cafe) + spots + 지도 + 리스트 + 검색 + 내주변 | 지도·리스트·검색·StampButton·MerchantsMap·동필터 |
| **혜택** (`merchants/page.tsx`) | merchants(전체) + 혜택칩 + 동필터 + 지도 + 리스트 | **가이드와 ~90% 동일 UI** |
| **코스** (`course/page.tsx`) | courses.ts + 페르소나칩 + 타임라인 | 지도(MerchantsMap) |
| **내조각** (`pieces/page.tsx`) | localStorage 수집물 | 독립적 (유일하게 진짜 다른 화면) |

→ **가이드와 혜택은 사실상 같은 화면이 두 번 있는 것.** 헤더·지도·검색바·리스트 렌더 코드 중복이 그 증거이고, 이게 "복잡함"의 근원이다.

**추가로 발견한 구조적 문제(데이터 실측):**
- 혜택 칩 3개 중 **고유가(goyuga)가 5,978/6,001건(99.6%)**, 그중 **단독 보유 4,704건(78%)**. 고유가는 "필터"가 아니라 "KB 사용처 전부"라는 뜻 → **변별력 0**(눌러도 6,001→5,978). 운영자의 "고유가는 중요치 않다"가 데이터와 정확히 일치.
- `PROGRAM_META`/`PROGRAM_ORDER`에 **날짜 조건이 전혀 없다** → 2026-08-31 종료 예정인 고유가가 9월에도 그대로 남는다.
- `Place`/`Merchant` 타입에 **강조(featured) 개념이 전혀 없다** → 운영자가 "특정 가게를 띄우는" 수단이 없다.
- 인스타 연계는 하단 `InstaCta.tsx`(전체 계정 링크) **하나뿐** → 인스타 콘텐츠와 앱 장소가 끊겨 있다.

## 2. 핵심 방향 한 줄 (무엇으로 통합할 것인가)

> **"발견" 단일 피드 하나로 합치고, 그 피드의 최상단을 운영자가 인스타에 올린 강조 가게(featured)가 차지한다.**
> 혜택·코스는 탭이 아니라 그 피드 안의 **필터/섹션**으로 녹이고, 인스타·취향은 탭이 아니라 앱 전반에 깔리는 **얇은 큐레이션 레이어**로 들어간다. 내조각(수집·공유)만 성격이 달라 탭으로 남긴다.

큐레이션·개인화·인스타를 **새 탭으로 추가하면 정확히 운영자 요구의 반대 방향**이다. 전부 "더 많은 화면"이 아니라 "첫 스크롤"과 "맥락 속 레이어"로 체감되게 한다.

## 2.5 v2 확정 변경 (운영자 추가 지시 — 2026-06-12)

### ① 관광 포인트만 남긴다 — 12업종 → 4조각
가맹점 6,001건에는 학원·병원·차량정비·마트 같은 **생활 업종**이 4,000여 건 섞여 있다. 이건 KB 혜택 데이터일 뿐 **여행자가 갈 곳이 아니다.** 소비자 화면은 관광 포인트만 남기고, 브랜드 톤으로 **4개의 "조각"** 으로 재구성한다.

| 조각 | 카피 | 채우는 데이터 | 수량 |
|---|---|---|---|
| 🍚 **먹거리** | 먹거리 | 가맹점 `c:"food"` | ~1,455 |
| ☕ **마실거리** | 마실거리 | 가맹점 `c:"cafe"` + 관광 `cat:"전망카페"` | ~379 |
| 🏛️ **볼거리** | 볼거리 | 관광 `문화재·박물관미술관·사찰·자연·꽃명소·전망·공원·기타` | ~43 |
| 🎨 **즐길거리** | 즐길거리 | 관광 `체험·축제` + **레저 가맹점 선별 21곳** | ~28 |

### ③ 고유가 뱃지 — 처음부터 완전 제거
날짜 자동 숨김(§7)보다 더 단순하게: **지금부터 `ProgramKey`에서 `goyuga`를 통째로 뺀다**(`"onnuri" | "market"`만). 데이터 `m.p`의 `"goyuga"` 문자열은 남겨두되 `PROGRAM_META`에 없으므로 표시 시 `m.p.filter(k => k in PROGRAM_META)`로 무시. 변별력 0(99.6%)이라 손실 없음. → §7의 날짜 게이팅 로직 불필요, 대신 onnuri/market 뱃지만 food/cafe 카드에 노출.

### 3.2 무엇을 합치고 무엇을 숨기는가

- **혜택 탭 → "발견"의 혜택 필터로 흡수.** 가이드엔 이미 동(`dong`) 드롭다운·`MerchantsMap`·리스트가 다 있다. `mode` 타입을 `"food" | "cafe" | "tour"`에 **`"benefit"` 추가**하고, benefit일 때만 온누리/전통시장 서브칩을 조건부 노출. `merchants/page.tsx`는 삭제(또는 `/`로 리다이렉트 — 기존 링크 보호).
- **코스 탭 → "발견" 안의 접이식 섹션으로 강등.** 코스는 사용 빈도가 가장 낮은 영감 콘텐츠. 탭 한 칸은 "매번 누르는 것"에 줘야 한다. `TodayPiece` 아래 가로 스크롤 카드 1줄 + 상세는 `/course/[persona]` 라우트로만 유지.
- **내조각만 탭 유지.** 수집·공유는 명확히 다른 목적지이고, 동시에 §4 취향 시그널의 소스가 된다.

## 4. 소비자 취향 맞춤 (비로그인 가벼운 개인화)

**원칙: 회원가입·추천 알고리즘·추천 탭 없음. 개인화는 "정렬 가중치 한 줄"이다.**

### 4.1 두 개의 시그널 소스 (둘 다 localStorage)
1. **명시 시그널 — 1회 온보딩(선택).** 첫 진입 시 칩 1줄 "어떤 나주 한 조각을 모으고 싶나요?" → 최대 2개 선택 또는 건너뛰기. 칩은 **코스 페르소나(`AGE_META`)와 동일 6종 재사용**(노포·향토맛 / 감성카페 / 사진스팟 / 가족나들이 / 역사·고분 / 미식코스) → 데이터 중복 방지.
   - `useStamps.ts` 패턴을 복제한 신규 `useTaste.ts`(`naju-taste-v1`, 값은 `string[]` 하나).
2. **암묵 시그널 — 내조각 분포.** 이미 `pieces`에 카테고리별 집계가 있다. 수집한 조각의 `c`(카테고리) 분포로 가중.

### 4.2 적용 (전부 무해한 폴백 보장)
- 메인 리스트/featured 정렬에서 **`tags ∩ taste` 겹침 카운트로 약한 가중**. 취향 미선택이면 기존 순서 그대로(무해).
- 취향칩 선택 시 상단에 "○○님의 나주" 인사 한 줄 + "오늘의 한 조각" 카피를 "오늘, 당신 취향의 한 조각"으로 변경(구조 동일, 카피만).
- **고유가는 취향 축에 절대 넣지 않는다** — 한시 제도라 9월부터 잔재가 남는다. 취향 태그는 상시 가치(향토맛·감성·사진·역사)만.

## 5. SNS(@piece_of_naju) 연계

**원칙: 인스타가 곧 큐레이션 레이어. 별도 "SNS 탭"은 만들지 않는다.** 인스타 게시물 1개 ↔ 앱 장소 1개를 정적으로 연결하는 작은 매핑 테이블을 도입해, 개인화·유입·강조의 **공통 재료**로 재사용한다.

```ts
// src/lib/data/insta.ts (신규, 정적 — 운영자가 인스타 글 올릴 때 한 줄 추가)
export interface InstaPost {
  id: string;          // 인스타 shortcode (URL은 instagram.com/p/{id}로 자동 생성)
  placeId: string;     // places.ts / merchants의 id와 연결
  caption: string;     // 앱에 보여줄 운영자 톤 한 줄
  tagIds: string[];    // 취향 태그(§4와 동일 6종)
  featured?: boolean;  // 강조 가게(§6)와 연동
  postedAt: string;
}
```

### 구체 기능
1. **장소 상세에 인스타 블록(`PlaceInsta.tsx` 신규):** 현재 상세는 `EditorQuote`·`InstaCta`(전체계정)만 있다. 여기에 "@piece_of_naju 에서 본 그곳" + 게시물 바로가기 1개를 `placeId` lookup으로 추가. **사진 크롤링 없이** 캡션+링크/oEmbed만(저작권 안전).
2. **딥링크 유입:** 인스타 캡션·스토리 링크를 `/place/{id}?from=insta`로. `?from=insta`를 읽어 "인스타에서 오셨네요 🧩" 토스트 1줄 → 길찾기/조각 담기 CTA 강조. **추적 백엔드 없이 UX 신호로만.**
3. **역방향 공유 루프:** 장소 공유 버튼이 `instagram.com/p/{shortcode}`도 함께 노출 → 친구에게 "여기 인스타" 형태로 재유포.
4. **운영 워크플로 통일:** "인스타에 가게 한 곳 올림 → `insta.ts`/`featured.ts`에 한 줄 추가 → 앱 첫 화면에 그 가게가 뜸." "한 조각씩 모은다" 브랜드 서사와 동작이 일치.

## 6. 강조 가게 큐레이션 (featured 운영 방식·신뢰)

**원칙: 큐레이션은 별도 시스템이 아니라 "발견" 피드의 첫 화면 그 자체.** 가게 본체 데이터(`places.ts`/`merchants.json`)는 건드리지 않고, **얇은 참조 레이어**를 별도 파일로 둔다.

```ts
// src/lib/data/featured.ts (신규)
export type FeaturedKind = "weekly" | "editor" | "sponsor";
export interface Featured {
  ref: string;            // places.id 또는 merchants.id
  source: "place" | "merchant";
  kind: FeaturedKind;     // 라벨/뱃지가 갈림 (신뢰 표기)
  rank: number;           // 노출 순서
  blurb: string;          // 이번 주 전용 한 줄 큐레이션 카피(인스타 톤)
  sns?: string;           // @piece_of_naju 해당 게시물 shortcode
  start: string;          // "2026-06-08"  노출 시작
  end: string;            // "2026-06-15"  자동 내림(§7과 같은 날짜 엔진)
}
```

**세 가지 원칙:**
1. **참조만 한다(`ref`).** 본체는 id로 가리킨다 → 중복·동기화 깨짐 방지.
2. **`start/end`로 자동 회전.** 운영자 손 없이 날짜로 만료(§7 고유가 게이팅과 동일 엔진 재사용 — 운영자가 배울 게 하나).
3. **`kind`로 정직 표기 — 광고와 진짜 추천을 섞지 않는다(신뢰의 핵심):**
   - `editor` → "에디터 픽"(대가 없음), `sponsor` → 명시적 "제휴" 뱃지 + "@piece_of_naju 제휴 가게" 한 줄(숨기지 않음), `weekly` → "이번 주 한 조각" 브랜드 슬롯.
   - 강조 카드라도 **별점·메뉴·거리·실주소는 일반 카드와 동일** 노출("광고라서 정보가 빈" 인상 제거).
   - **동시 노출 ≤ 3 상수**로 피드가 광고판 되는 걸 구조적으로 차단.

**UI:** 기존 무상태 카드 `TodayPiece`를 모델 삼아 **`WeeklyPiece`(가칭)** 를 만들되 데이터 출처만 날짜해시 → `featured.ts`로 교체. 묶음은 기존 `DragScroll` 재사용. `InstaCta`를 강조 카드의 [인스타에서 보기]로 재사용. 신뢰 카피는 별점·과장 대신 **"왜 이번 주 이곳인가" 한 문장**(메모리의 비-AI 에디토리얼 손맛).

**수익(가볍고 정직, 백엔드 0):** 주간 스폰서 슬롯 1자리(`kind:"sponsor"`, `start/end`로 기간 자동 관리, 결제는 앱 밖 인스타 DM/계좌). 인스타 게시물 + 앱 슬롯 묶음 판매. **클릭당 과금·실시간 입찰·외부 광고 SDK는 채택하지 않음**(원칙 충돌).

## 7. 혜택 단순화 — 고유가 완전 제거 (v2 확정)

> **v2 변경:** 운영자 지시로 고유가는 날짜 자동 숨김이 아니라 **처음부터 통째로 제거**(§2.5 ③). 아래 7.1 날짜 게이팅 방식은 **불채택** — 더 단순한 "PROGRAM에서 goyuga 삭제"로 대체한다. 종료가 연장되는 등 되살릴 필요가 생기면 7.1 패턴을 참고용으로 남겨둔다.

**확정 방식(채택):** `ProgramKey = "onnuri" | "market"`, `PROGRAM_META`/`PROGRAM_ORDER`에서 `goyuga` 제거. 모든 카드 뱃지 렌더를 `m.p.filter(k => k in PROGRAM_META).map(...)`로 가드(데이터의 goyuga 문자열은 무시). 혜택 칩 자체를 없애고 온누리·전통시장은 **food/cafe 카드의 뱃지로만** 노출.

<details>
<summary>참고(불채택): 7.1 날짜 게이팅 방식</summary>

### 7.1 단일 진실원천(SSOT) — 날짜 상수 하나로 전부 게이팅
`merchants.ts`의 `PROGRAM_META`에 `endsAt`을 박고 파생 헬퍼를 export. 모든 화면은 `PROGRAM_ORDER` 대신 `activePrograms()`/`visiblePrograms()`를 쓴다.

```ts
// src/lib/data/merchants.ts (PROGRAM_META 교체 + 헬퍼 추가)
export const PROGRAM_META: Record<ProgramKey,
  { label: string; short: string; color: string; endsAt: string | null }> = {
  goyuga: { label: "고유가 피해지원금", short: "고유가", color: "#e8702a", endsAt: "2026-08-31" },
  onnuri: { label: "온누리상품권",     short: "온누리", color: "#2f7d4f", endsAt: null },
  market: { label: "전통시장",         short: "전통시장", color: "#9c5a2f", endsAt: null },
};

export function isProgramActive(k: ProgramKey, now: Date = new Date()): boolean {
  const ends = PROGRAM_META[k].endsAt;
  if (!ends) return true;
  // KST(+09:00) 자정 컷오프 — UTC 빌드에서 9시간 어긋남 방지(반드시 명시)
  return now.getTime() <= new Date(`${ends}T23:59:59+09:00`).getTime();
}
export const activePrograms = (now = new Date()) =>
  PROGRAM_ORDER.filter((k) => isProgramActive(k, now));
export const visiblePrograms = (p: ProgramKey[], now = new Date()) =>
  p.filter((k) => isProgramActive(k, now));
```

**왜 이 방식:** `merchants.json`은 `"p":["goyuga",...]` 그대로 둠 → **재크롤링/재빌드 불필요.** 종료가 연장/철회돼도 `endsAt` 한 줄만 수정. featured의 `start/end`도 같은 패턴 → 만료 사고방식 하나로 통일.

### 7.2 적용 지점 (전부 프런트, API 무변경 — 현재 코드 실측 5곳)
- **혜택 칩 렌더:** `PROGRAM_ORDER` → `activePrograms()` (`src/app/merchants/page.tsx` 칩 목록). 9/1 00:00 KST부터 고유가 칩 자동 소멸, 온누리·전통시장 2개만 남음.
- **가맹점 뱃지 `m.p.map` → `visiblePrograms(m.p).map`** 4곳:
  - `src/components/home/TodayPiece.tsx:57`
  - `src/app/page.tsx` (리스트 카드)
  - `src/app/merchants/page.tsx` (카드)
  - `src/components/map/MerchantsMap.tsx` (지도 말풍선)
- **(선택) API 방어:** `src/app/api/merchants/route.ts`의 `program` 파라미터를 `isProgramActive`로 필터 — 북마크/외부 링크 방어용. 없어도 동작 무해.

### 7.3 혜택 표기 단순화 (지금 바로, 종료 전에도)
- **고유가 칩 제거**(변별력 0). 대신 **헤더 안내 한 줄로 강등**, 종료일 자동 반영:
  ```tsx
  {isProgramActive("goyuga") && (
    <p className="text-[11px] text-ink-soft">KB 사용처는 8/31까지 고유가 피해지원금 대상이에요</p>
  )}
  ```
  → 능동 필터(칩)가 아니라 안내문으로 내려 필터 UI는 **상시 온누리·전통시장 2개**로 고정. 8/31 지나면 이 문장도 자동 소멸.
- **빈 카드 함정 방지(중요):** 종료 후 4,704건(78%)이 "혜택 0"이 된다. 현재 코드(`m.p.length>0 && ...`)상 뱃지 줄이 그냥 사라져 일반 가게처럼 보이는데, 이는 오히려 운영자 의도("강조 가게 느낌")와 정합 — 고유가는 변별력 0이었으니. 종료 후 **남는 온누리·전통시장 뱃지 = 진짜 차별화 시그널**이 되어 큐레이션 효과가 올라간다. 별도 작업 불필요.

### 7.4 테스트 (날짜 조건이 핵심)
```ts
isProgramActive("goyuga", new Date("2026-08-31T15:00:00+09:00")) // true (종료 당일)
isProgramActive("goyuga", new Date("2026-09-01T00:00:00+09:00")) // false (자동 소멸)
activePrograms(new Date("2026-09-01T00:00+09:00"))               // ["onnuri","market"]
```

## 9. 안 할 것 (스코프 컷)

- **새 탭 추가 금지.** "추천 탭", "SNS 탭", "취향 탭" 전부 X — 운영자 요구의 정반대. 큐레이션=피드 상단, 인스타=맥락 레이어, 취향=정렬 가중치.
- **API 분리·증설 금지.** `/api/merchants` 하나 유지. 혜택 흡수도 같은 엔드포인트(`?geo=naver` 추가 호출)로.
- **`merchants.json` 재크롤링/재빌드 금지.** 고유가 만료는 데이터가 아니라 코드 상수(`endsAt`)로만. 데이터의 `goyuga` 값은 남기고 표시단에서 거른다.
- **로그인·계정·서버 추천 알고리즘 금지.** 개인화는 localStorage 시그널 + 단순 겹침 카운트 정렬뿐. 무선택 시 기존 순서(무해).
- **사진 크롤링 금지.** 인스타 자체 사진/공공누리만. featured/상세는 텍스트(캡션)+링크/oEmbed.
- **고유가를 취향·featured 카피에 섞지 않기.** 한시 제도라 9월 잔재 위험. 상시 가치(향토맛·감성·사진·역사)만.
- **클릭당 과금·실시간 입찰·외부 광고 SDK 금지.** 수익화는 정적·주간·소수(≤3) 슬롯으로만.
- **featured를 가게 본체 데이터에 인라인 금지.** 반드시 별도 참조 레이어(`featured.ts`, id 참조) — 동기화 깨짐·중복 방지.
